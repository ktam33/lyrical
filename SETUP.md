# Cantonese Lyrics Translator - Setup Instructions

## Prerequisites
- Node.js 18+ installed
- OpenAI API key

## Setup

1. **Install dependencies:**
   ```bash
   npm install
   ```

2. **Configure environment variables:**
   ```bash
   cp .env.example .env.local
   ```

   Edit `.env.local` and add your OpenAI API key:
   ```
   OPENAI_API_KEY=your_actual_openai_api_key_here
   ```

3. **(Optional) Rebuild the dictionary database:**
   ```bash
   npm run seed-db
   ```
   `data/lyrical.db` is already checked into the repo, seeded from `data/Cantonese_Anki.txt`. Only run this if you've edited that source file and want to regenerate the database — note it overwrites `data/lyrical.db`, including any edits made through the `/entries` page.

4. **Run the development server:**
   ```bash
   npm run dev
   ```

5. **Open your browser:**
   Navigate to `http://localhost:3000`

## Usage

### Translator (`/`)
1. Paste Cantonese song lyrics into the text area
2. Click "Translate Lyrics" to get:
   - Line-by-line contextual translation
   - Analysis of new characters not in the dictionary
   - Suggested definitions for new characters
3. Input and results stay in place if you navigate to the dictionary and back

### Dictionary browser (`/entries`)
1. Search entries by character, Jyutping, or definition, and page through results
2. Click "Edit" on a row to update its character, Jyutping, definition, or source, then "Save"

## Features

- **Contextual Translation**: Uses GPT-4 to provide meaningful translations that capture the song's essence rather than literal word-for-word translation
- **SQLite Dictionary**: Character data lives in `data/lyrical.db` (table `entries`), queried against lyrics to find known characters
- **New Character Detection**: Identifies characters not in the dictionary
- **Contextual Definitions**: Generates appropriate definitions and Jyutping for new characters based on the song's context
- **Dictionary Browser/Editor**: Search, page through, and edit dictionary entries directly from the web UI
- **Persistent Translator State**: Lyrics/translation/analysis state is shared via React Context so it survives navigation to the dictionary page

## File Structure

- `/data/Cantonese_Anki.txt` - Source Anki deck export (character, jyutping, definition, source)
- `/data/lyrical.db` - SQLite database (table: `entries`), generated by `scripts/seed-db.js`
- `/scripts/seed-db.js` - Parses `Cantonese_Anki.txt` into `lyrical.db`
- `/src/app/api/translate/` - Translation API endpoint
- `/src/app/api/analyze-characters/` - Character analysis API endpoint
- `/src/app/api/entries/` - Dictionary list/search + update-by-id API endpoints
- `/src/app/entries/` - Dictionary browse/edit page
- `/src/components/` - React components (LyricsInput, TranslationDisplay, EntriesBrowser, ...)
- `/src/context/TranslatorContext.tsx` - Shared translator state across routes
- `/src/utils/db.ts` - SQLite access layer (list/search/update entries)
- `/src/utils/database.ts` - In-memory character lookup used by the translator, backed by `db.ts`
- `/src/utils/openai.ts` - Shared OpenAI chat-completion + JSON-parsing helper
